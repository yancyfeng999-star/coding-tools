# Coding Tools UI 基础体验与 Mac 通用能力设计

> 日期：2026-08-14
> 状态：设计审核稿
> 范围：Coding Tools 仓库
> 设计方向：保留现有四标签结构，仅参考 Codex 的视觉克制、排版层级和信息密度
> 开源协议：Apache-2.0
> 本文不代表：源码已经修改、App 已构建、运行时已验证、版本已发布或 GitHub Release 已上线

## 1. 背景

Coding Tools 已经具备工具目录、本地安装探测、最新版本查询、安装流程、Sparkle 应用更新、菜单栏、主题切换和中英文资源等基础模块，但当前用户体验存在明显断层：

1. 主题模块只负责浅色、深色和跟随系统，没有统一的字体、字号、间距、颜色、圆角和表面层级。
2. 页面大量直接使用 `.title`、`.headline`、`.caption`、`.blue`、`.orange`、渐变、阴影和悬停缩放，导致视觉语言不统一。
3. 工具卡片已经能显示本地版本和最新版本，但工具详情页仍固定提供“安装”按钮，用户无法判断应该安装、更新、修复还是重新安装。
4. 工具详情关闭按钮依赖 toolbar，安装弹窗没有固定在顶角的关闭入口，窗口较窄或系统 toolbar 调整时可发现性不足。
5. 设置页已经定义检查更新按钮，但没有将该按钮渲染到更新区域；菜单栏仅在部分更新状态下显示更新入口。
6. 问题报告和反馈入口仅出现在菜单栏，主窗口缺少稳定入口。
7. 已有检测、更新和安装能力没有经过统一的 UI 展示状态层，导致不同页面各自判断并产生冲突。

本设计解决这些产品层和接入层问题，同时保留现有信息架构，避免将本轮扩大为主导航重写。

## 2. 设计目标

### 2.1 用户目标

用户在任何页面都应快速回答以下问题：

- 我现在在哪里？
- 这个工具是否已安装？
- 本地是什么版本？
- 是否存在新版本？
- 当前最合适的动作是什么？
- 操作会通过什么来源执行、需要什么权限、可能产生什么影响？
- 如果失败，我应该重试、修复、刷新还是报告问题？
- Coding Tools 自身是否有更新？

### 2.2 产品目标

- 保留首页、工具、内容、设置四标签结构。
- 建立可复用但不过度抽象的轻量设计体系。
- 让工具卡片、详情页、安装弹窗和菜单栏使用同一状态事实。
- 让应用更新和工具更新在概念、状态和操作上保持分离。
- 把反馈、诊断、帮助和可访问性纳入 Mac 软件基础体验。
- 使所有状态在浅色、深色、跟随系统、高对比度和 Reduce Motion 环境中可用。

### 2.3 工程目标

- 复用现有 `AppState`、`InstallationProbe`、`LatestVersionProvider`、安装器和 Sparkle 更新状态机。
- 在领域事实和 SwiftUI 视图之间增加统一的展示状态映射。
- 避免视图自行拼装版本判断、按钮标题、颜色和恢复动作。
- 通过状态矩阵测试覆盖主要分支，而不是只依赖截图或人工点击。

## 3. 非目标

本轮不做以下事项：

- 不把四标签导航改成 Codex 式主侧栏。
- 不进行像素级 Codex 复刻。
- 不引入第三方字体。
- 不重写 Catalog、安装器或 Sparkle。
- 不新增在线账号、云同步、遥测平台或私有反馈后端。
- 不默认收集崩溃日志、用户路径、终端输出或工具配置。
- 不以本文作为本地构建、签名、notarization、GitHub Release、Sparkle 更新成功或用户安装成功的证据。
- 不在本轮设计阶段构建、启动或安装 App。

## 4. 设计原则

### 4.1 克制

界面通过层级、间距、对齐和文字表达重点，不依赖大面积渐变、阴影、彩色背景或动画。

### 4.2 状态先于装饰

用户首先看到安装状态、本地版本、最新版本和下一步动作，工具分类、风险、教程等信息位于清晰的次级层。

### 4.3 一个事实来源

工具卡片、详情页、安装弹窗和菜单栏不得分别实现“是否需要更新”的逻辑。领域事实只映射一次，所有视图只渲染结果。

### 4.4 用户主动控制

安装、更新、诊断复制、日志导出、自动下载和反馈提交都必须由用户明确触发。

### 4.5 原生 Mac 体验

优先使用系统字体、系统强调色、原生焦点环、标准快捷键、VoiceOver 语义和系统外观变化，而不是模拟网页控件。

## 5. 信息架构

继续保留现有四个标签：

1. 首页：产品概览、最近使用、收藏、必要的应用更新提示。
2. 工具：分类、搜索、工具目录、本地状态和操作。
3. 内容：教程、文档和可信外部资源。
4. 设置：外观、语言、应用更新、支持与反馈、诊断、关于。

### 5.1 导航调整边界

- `RootView` 继续使用 `TabView`。
- 统一四个标签的标题、图标、页面背景和内容边距。
- 搜索仍属于工具页，不上升为全局搜索。
- 设置入口同时保留主窗口标签、菜单栏和标准快捷键 `Command-,`。
- 不增加第二套主导航。

## 6. 视觉系统

### 6.1 字体

使用 macOS 系统字体 SF Pro；版本、路径、命令和日志使用 SF Mono。

| 语义角色 | SwiftUI 建议 | 字重 | 用途 |
|---|---|---|---|
| pageTitle | `.title2` | semibold | 页面主标题 |
| sectionTitle | `.headline` | semibold | 分区标题 |
| itemTitle | `.body` | semibold | 工具名、卡片标题 |
| body | `.body` | regular | 正文、字段值 |
| supporting | `.callout` | regular | 辅助说明 |
| metadata | `.caption` | regular/medium | 状态、时间、分类 |
| tinyMetadata | `.caption2` | regular | 极少量次级元数据 |
| code | `.system(.body, design: .monospaced)` | regular | 命令、路径、日志 |
| compactCode | `.system(.caption, design: .monospaced)` | regular | 版本号、构建号 |

约束：

- 页面不得直接使用任意固定字号，只有设计令牌内部可以定义尺寸策略。
- 正文不使用等宽字体。
- 版本号使用等宽数字或等宽字体，保证对齐。
- 按钮文本不全大写。
- 单行字段必须设置合理截断，并允许复制关键值。
- 不通过缩小文字解决布局溢出。

### 6.2 间距

采用 4pt 网格：

| 令牌 | 数值 | 用途 |
|---|---:|---|
| space1 | 4 | 图标与短文本 |
| space2 | 8 | 紧凑控件内部 |
| space3 | 12 | 卡片内部行间距 |
| space4 | 16 | 标准卡片内边距 |
| space5 | 20 | 页面紧凑边距 |
| space6 | 24 | 页面区块间距 |
| space8 | 32 | 大区块分隔 |

### 6.3 圆角与边框

- 小型徽章：6pt。
- 标准卡片和字段组：8pt。
- 大型面板、弹窗内部区块：10pt。
- 标准边框使用 1px 语义色 `subtleBorder`。
- 不叠加多层阴影。
- 浮层仅使用系统材质或非常轻的单层阴影。

### 6.4 颜色

颜色必须通过语义令牌提供：

- `appBackground`
- `contentBackground`
- `elevatedSurface`
- `selectedSurface`
- `hoverSurface`
- `subtleBorder`
- `strongBorder`
- `primaryText`
- `secondaryText`
- `tertiaryText`
- `accent`
- `success`
- `warning`
- `danger`

约束：

- 工具分类色只用于小图标或小徽章，不作为整张卡片背景。
- 成功、警告和危险色只表达状态。
- 主操作使用系统 accent，不固定为蓝色。
- 文字不能只通过颜色表达状态，必须同时提供图标或文案。
- 支持系统 Increase Contrast。

### 6.5 动效

- 移除卡片悬停缩放。
- 悬停只改变轻微背景或边框。
- 状态切换动画控制在 120–180ms。
- Reduce Motion 开启后取消位移和缩放，仅保留必要淡入淡出或无动画切换。

## 7. 主题行为

主题继续提供：

- 跟随系统
- 浅色
- 深色

### 7.1 跟随系统恢复

当前主题实现只在指定浅色或深色时设置 `NSApplication` 和窗口 appearance，切回跟随系统时不主动清除先前设置。设计要求：

- 切回跟随系统时恢复 App 和现有窗口的继承行为。
- 新窗口必须继承当前主题设置。
- 系统外观变化时，跟随系统模式实时更新。
- 菜单栏图标在所有模式下保持可辨识。
- 主题设置持久化，但不得覆盖系统辅助显示设置。

## 8. 页面设计

### 8.1 Root

- 继续使用四标签 `TabView`。
- 最小窗口尺寸保留，但检查小窗口下的标题、按钮和工具栏压缩。
- Toast 使用统一宽度、语义色和关闭行为。
- 每个标签使用一致的页面背景和顶部节奏。
- 深链进入工具或设置时保留现有行为。

### 8.2 首页

- 顶部不使用大面积装饰性标题。
- 优先显示最近工具、收藏和需要处理的状态。
- 应用存在更新时显示紧凑更新提示；无更新时不占据大卡片空间。
- 空状态说明用户下一步，而不是只显示空图标。

### 8.3 工具目录

- 保留目录内现有分类侧栏。
- 工具卡片移除渐变、重阴影和悬停缩放。
- 卡片固定显示工具名、分类、健康状态、本地版本或目标版本。
- 主操作始终可见，不依赖 hover。
- 收藏和详情入口可以在 hover 时增强，但键盘和 VoiceOver 必须始终可访问。
- 点击卡片进入详情，点击主操作直接进入对应确认流程；两个点击区域不得冲突。

### 8.4 内容页

- 与工具页共用字体、表面和空状态。
- 外部链接明确显示域名和外链图标。
- 可信来源校验失败时给出原因和恢复动作。

### 8.5 设置页

设置页按以下顺序组织：

1. 外观
2. 语言
3. 应用更新
4. 通用
5. 支持与反馈
6. 诊断与恢复
7. 关于

设置项使用标准行高和右侧值，不将 About 内容做成与其他页面风格不一致的大卡片。

## 9. 工具详情设计

### 9.1 固定头部

工具详情继续以 sheet 呈现，但不依赖可能被系统压缩的 toolbar 承载关键操作。

头部包含：

- 左侧：工具图标、工具名、分类、健康状态。
- 中部或标题下方：本地版本与最新版本摘要。
- 右上角：始终可见的关闭按钮。
- 状态区域：主操作按钮。
- 收藏：次级图标按钮。

关闭行为：

- `Esc` 关闭没有运行中操作的详情页。
- 关闭详情不会自动取消已明确开始且由安装弹窗管理的操作。
- 详情与安装弹窗不得出现两个意义相同但行为不同的关闭按钮。

### 9.2 本地状态面板

详情页新增“本地状态”面板：

| 字段 | 显示规则 |
|---|---|
| 状态 | 已安装、可更新、损坏、未安装、无法确认、检测中 |
| 本地版本 | 检测到时显示；未知时明确显示“无法读取” |
| 最新版本 | 查询成功时显示；未查询或来源不支持时区分显示 |
| 检测路径 | 中间截断，可复制 |
| 架构 | arm64、x86_64、Universal 或未知 |
| 安装来源 | Homebrew、npm、Mise、官方制品等 |
| 上次检查 | 本地化相对时间和可选精确时间 |
| 刷新 | 只刷新当前工具的本地状态和最新版本 |

用户目录、Token、签名下载 URL 和完整环境变量不得出现在默认状态面板。

### 9.3 操作矩阵

| 展示状态 | 主操作 | 次级操作 | 说明 |
|---|---|---|---|
| checking | 检测中，禁用 | 无 | 防止检测期间误判 |
| notInstalled | 安装 | 查看安装方式、打开官网 | 有安全 option 才可安装 |
| installedCurrent | 打开/启动 | 重新安装、重新检查 | 最新版本已知且不高于本地 |
| updateAvailable | 更新至目标版本 | 打开、查看来源 | 明确显示本地到目标版本 |
| broken | 修复 | 重新检测、打开诊断 | 不把损坏状态写成普通安装 |
| versionUnknown | 重新检查 | 打开本地路径、重新安装 | 不虚构“已是最新” |
| sourceUnavailable | 不可安装，禁用 | 打开官网、反馈问题 | 说明缺少可信安装来源 |
| operationRunning | 显示进度，禁用 | 取消 | 同一工具禁止重复提交 |
| operationFailed | 重试 | 复制错误摘要、反馈 | 使用稳定错误分类 |

### 9.4 展示状态模型

新增统一的展示状态，不要求改变现有领域模型：

```swift
enum ToolPresentationStatus: Equatable {
    case checking
    case notInstalled(latestVersion: String?)
    case installedCurrent(localVersion: String, latestVersion: String?)
    case updateAvailable(localVersion: String, latestVersion: String)
    case broken(localVersion: String?, reason: ToolStatusReason?)
    case versionUnknown(path: String?)
    case sourceUnavailable(reason: ToolStatusReason)
}

enum ToolPrimaryAction: Equatable {
    case install
    case open
    case update(targetVersion: String)
    case reinstall
    case repair
    case refresh
    case retry
    case unavailable
}
```

命名可在实施计划中按项目现有模块风格调整，但必须保留统一映射原则。

## 10. 安装与更新工具流程

### 10.1 安装确认

安装确认页必须显示：

- 工具名
- 当前版本（如果存在）
- 目标版本（如果已知）
- 安装来源
- 权限范围
- 命令或动作预览
- 影响范围
- 风险等级与解释
- 取消和确认按钮
- 右上角关闭按钮

没有安全安装 option 时不得创建假的默认 option。

### 10.2 运行中

- 显示明确状态：准备、下载、验证、安装、安装后检测。
- 日志默认折叠，用户可展开和复制脱敏摘要。
- 禁止重复启动同一个操作。
- 取消操作必须连接到底层 Task 或进程，不能只改变 UI。
- 关闭按钮在运行中被点击时，确认“取消安装并关闭”。

### 10.3 成功

- 立即刷新当前工具的 `InstallationProbe`。
- 重新查询需要时的最新版本。
- 显示已安装版本和路径。
- 主操作变为“打开”或产品允许的下一步。
- 如果安装器成功但探测失败，显示“安装完成，状态待确认”，不得写成完全成功。

### 10.4 失败

错误至少区分：

- 网络不可用
- 来源不可用
- 校验失败
- 权限被拒绝
- Helper 不可用
- 命令退出失败
- 用户取消
- 安装完成但检测失败
- 本地版本无法解析

每个错误提供一个主要恢复动作和一个可选诊断动作。

## 11. 应用更新设计

应用自身更新继续使用 Sparkle，与工具更新分开。

### 11.1 固定入口

- 设置页始终显示“检查更新”。
- 菜单栏始终显示“检查更新”，快捷键为 `Command-U` 或项目最终选定的无冲突快捷键。
- 主应用菜单的标准位置增加“检查更新”，如果现有命令体系允许。
- 首页只在有新版本、失败或需要重启时显示紧凑提示。

### 11.2 更新状态

| 状态 | 主文案 | 操作 |
|---|---|---|
| idle | 尚未检查或显示上次检查时间 | 检查更新 |
| checking | 正在检查 | 禁用重复点击 |
| upToDate | 已是最新版本 | 再次检查 |
| available | 新版本可用 | 查看并下载/更新 |
| downloading | 正在下载 | 显示进度，可按 Sparkle 能力取消 |
| extracting | 正在准备更新 | 显示进度 |
| readyToInstall | 已准备安装 | 安装并重启 |
| installing | 正在安装 | 禁止重复操作 |
| installed | 更新已安装 | 按实际流程提示重启或完成 |
| failed | 更新失败 | 重试、复制错误摘要 |

### 11.3 更新详情

可用时显示：

- 当前版本和构建号
- 新版本和构建号
- 发布日期
- 下载大小
- 最低 macOS 版本
- 更新说明
- 更新通道
- 更新来源

如果 appcast 未提供某字段，显示“未提供”，不得伪造。

### 11.4 自动更新

- 默认保留用户控制。
- 自动检查和自动下载必须是独立设置。
- 自动安装或强制重启不进入本轮 P0。
- Beta 通道进入 P2，前提是签名、appcast、隐私说明和回退策略完成。

## 12. 反馈、帮助与诊断

### 12.1 入口

在设置页“支持与反馈”、状态栏菜单和应用菜单提供：

- 报告问题
- 功能建议
- 查看项目主页
- 查看帮助
- 复制诊断摘要

### 12.2 GitHub 接入

- 报告问题打开仓库 GitHub Issue 模板。
- 功能建议打开 GitHub Discussions Ideas。
- 自动填入应用版本、构建号、macOS 版本和 CPU 架构。
- 不自动上传日志。
- 链接打开失败时显示可复制 URL，而不是无反馈。

### 12.3 诊断摘要

默认允许包含：

- Coding Tools 版本和构建号
- macOS 版本
- CPU 架构
- 当前主题和语言
- Catalog 状态摘要
- 更新状态码
- 选定工具的状态码、版本和来源类型

默认禁止包含：

- 用户名和 Home 绝对路径
- Token、API Key、Cookie、Authorization Header
- 完整环境变量
- 终端完整输出
- 签名下载 URL
- 未经确认的工具配置内容

复制前显示预览和包含项，让用户确认。

## 13. Mac 通用能力分级

参考同目录“智额”项目的 Mac 通用能力方案，但按 Coding Tools 的产品性质裁剪。

### 13.1 P0：本轮核心

- 统一主题、字体、字号、间距、表面和状态色。
- 工具详情、本地版本、最新版本和操作状态闭环。
- 工具安装、更新、修复、重试和取消体验。
- 应用检查更新固定入口和完整状态。
- 反馈、问题报告和 About 信息。
- VoiceOver、键盘、焦点、高对比度和 Reduce Motion。
- 统一错误文案和恢复动作。

### 13.2 P1：基础能力补齐

- 首次启动说明和兼容性检查。
- 诊断页面和脱敏摘要。
- 收藏、最近使用和用户设置的安全导出/导入。
- Catalog 缓存状态、刷新和安全重置。
- 异常退出后的恢复提示。
- 帮助、快捷键和常见问题。
- 设置 schema 迁移和损坏恢复。

### 13.3 P2：发布体系成熟后

- Beta 更新通道。
- 用户可控的自动下载。
- 明确 opt-in 的匿名崩溃诊断。
- 更新失败回退说明和恢复流程。
- 更完整的运行时性能与生命周期诊断。

## 14. 前后端接入

### 14.1 现有能力

当前已经存在：

- `InstallationProbe`：本地版本、路径、架构、Bundle ID、Team ID、健康状态和检查时间。
- `InstallationDetector`：CLI 和 App 的路径、版本与架构检测。
- `LatestVersionProvider`：最新版本查询和缓存。
- `AppState.refreshProbe` / `refreshProbes`：刷新本地状态。
- `AppState.refreshLatestVersions`：刷新最新版本。
- `AppState.isOutdated`：比较本地与最新版本。
- 安装完成后的单工具重新检测。
- Sparkle `UpdateState` 和 `UpdateFlowModel`。

### 14.2 接入目标

```text
Catalog / InstallationProbe / LatestVersionProvider
                        ↓
             ToolPresentationState
                        ↓
    Catalog Card / Detail / Install Sheet / Menu Bar
```

应用更新保持独立：

```text
Sparkle / UpdateFlowModel
             ↓
        App Update UI
             ↓
Settings / Home Notice / App Menu / Status Menu
```

### 14.3 状态一致性

- Catalog 卡片和详情页必须显示同一本地版本和最新版本。
- 安装成功后先刷新本地探测，再决定主操作。
- 最新版本查询失败不能把工具错误标记为“已是最新”。
- 本地探测失败不能默认写成“未安装”。
- 远程来源不支持版本查询时必须显示“最新版本不可用”。
- 所有刷新操作提供 loading、成功、失败和上次更新时间。

### 14.4 刷新策略

- App 启动后进行现有批量探测。
- 打开详情时，如果状态缺失或过期，刷新当前工具。
- 用户可手动刷新当前工具。
- 安装、更新、修复结束后刷新当前工具。
- 避免进入详情时重复发起相同请求。
- 最新版本缓存继续尊重 provider 的缓存和频率限制。

## 15. 可访问性

### 15.1 VoiceOver

- 工具卡片作为一个可理解容器，读出工具名、安装状态、本地版本和主操作。
- 图标按钮必须有可本地化的 accessibility label 和 help。
- 状态不能只读“绿色”或“红色”。
- 进度需要可读的阶段和百分比。
- 关闭、收藏、安装、更新和刷新不得共享模糊标签。

### 15.2 键盘

- Tab 顺序与视觉顺序一致。
- `Esc` 关闭可安全关闭的弹窗。
- `Return` 触发明确的默认操作。
- `Command-,` 打开设置。
- 检查更新快捷键不得与现有命令冲突。
- 工具卡片的主操作和详情入口都可通过键盘访问。

### 15.3 对比度与动效

- 文字和背景满足 WCAG AA 的可读性目标。
- Increase Contrast 下边框和选中状态更明显。
- Reduce Motion 下取消 hover 缩放和非必要转场。
- 浅色和深色主题都不得使用仅在单一模式可辨识的透明度。

## 16. 本地化与文案

- 所有新增用户文案进入 `Localizable.xcstrings`。
- 中英文同时补齐，不以英文 fallback 代替正式翻译。
- “应用更新”和“工具更新”必须使用不同文案。
- “未安装”“无法确认”“检测失败”是三个不同状态。
- “安装完成但检测失败”不得简化成“安装成功”。
- 错误文案使用“发生了什么 + 用户可以做什么”的结构。
- 版本号、构建号、路径和错误码允许选择复制。

## 17. 隐私与安全

- 继续遵守可信 Catalog、受控安装 option 和来源验证边界。
- UI 改造不得绕过 ManifestSecurity 或安装器权限模型。
- 不因为需要“安装按钮”而为缺少 option 的工具构造默认命令。
- 不在错误提示、Toast、反馈 URL 或诊断摘要中放入密钥和完整用户路径。
- GitHub 反馈链接在打开前只附带安全的系统元数据。
- 自动更新设置不得削弱 Sparkle 签名验证。
- 用户关闭运行中安装时，必须通过真实取消能力处理。

## 18. 开源文档要求

项目使用 Apache-2.0。UI 与基础能力完成时同步更新：

- `README.md`：界面、更新、反馈和隐私说明。
- `README.zh-CN.md`：中文同步内容。
- `CHANGELOG.md`：用户可见改动。
- `CONTRIBUTING.md`：视觉令牌、状态模型和本地化约束。
- `SECURITY.md`：安全问题报告入口，不与普通反馈混用。
- Issue 模板：版本、系统、复现步骤和脱敏提示。
- Screenshots：只能使用实际运行候选版本截图，不能用设计图冒充已实现界面。

## 19. 验收标准

### 19.1 视觉

- 四个标签使用同一字体层级、间距、颜色和表面体系。
- 不再存在工具卡片渐变、重阴影和 hover 缩放。
- 浅色、深色和跟随系统切换一致。
- 从固定主题切回跟随系统后，窗口真正恢复系统外观。
- 关键文本在最小窗口宽度下不被不可恢复地裁掉。

### 19.2 工具状态

- 未安装显示安装。
- 已安装且最新不显示更新。
- 本地版本低于最新版本时显示目标版本更新。
- 损坏显示修复。
- 状态未知显示重新检查，而不是未安装。
- 详情页显示本地版本、最新版本、路径、架构和上次检查时间。
- 卡片与详情状态一致。

### 19.3 弹窗

- 工具详情右上角始终有关闭按钮。
- 安装弹窗右上角始终有关闭按钮。
- 运行中关闭会触发清晰确认。
- 没有安全安装 option 时不显示可用安装确认。

### 19.4 更新与反馈

- 设置页始终能检查更新。
- 菜单栏始终能检查更新。
- 检查中防止重复请求。
- 反馈入口可从主窗口找到。
- Issue 预填版本、构建号、macOS 和架构。
- 日志和诊断信息不自动上传。

### 19.5 可访问性

- 所有关键操作可通过键盘完成。
- VoiceOver 能读出工具状态、版本和按钮目的。
- Increase Contrast 和 Reduce Motion 有明确行为。
- 状态不只依赖颜色。
